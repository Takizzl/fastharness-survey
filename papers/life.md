## 一句话

轻量模型筛选事件，文件记忆保留证据，Coding Agent提炼并注册查询工具与技能。

## 问题

持续观察产生大量冗余信息，未来问题未知，既有工具也可能缺少利用历史证据的方法。

## 方法


**问题：机器人在任务之间也会观察到人物、物体与环境变化，如何选择值得保留的观察，并让过去的证据支持未来尚未知晓的任务？**

**方法：RoboBeats 筛选事件，Plastic Memory 保存图像与结构化记录，EDM 将解决问题时探索出的程序提炼成可复用工具、技能和记忆字段生成器。**

这里的经验不仅是操作成功／失败轨迹，也包括持续运行中看到的事件、状态、时间和位置。记忆保存“发生过什么”的证据，能力库保存“如何提取和利用这些证据”的方法。

[对应论文原图](../reports/life.html)

| 模块 | 输入 | 处理与输出 |
|---|---|---|
| RoboBeats | 时间戳图像、自然语言监控条件 | 输出条件分数，触发响应或将观察交给记忆写入器 |
| Memory writer / consolidation | 被选中的观察窗口、图像与时间 | 描述事件与状态，关联人物、物体、地点和活动 |
| Plastic Memory | 图像、位姿、来源及派生字段 | 保存可追溯证据，支持过滤、关联、检索和历史重扫 |
| Execution Agent | 用户问题、当前上下文、检索证据及已有工具 | 回答问题或调用物理动作，必要时回看原图或现场确认 |
| Coding Agent + EDM | 能力缺口、历史证据、探索程序与执行反馈 | 构建并注册工具、技能、字段和索引生成器 |

来源：§1–2、图2、§4–5。

## 经验采集：RoboBeats 何时触发

**门控模型负责“何时需要进一步处理”，完整语义描述由下游 writer 生成。**

[对应论文原图](../reports/life.html)

| 模式 | 监控内容 | 结果用途 |
|---|---|---|
| Condition Tracking | Agent 或预设规则给出的条件，如电梯门打开、抓取完成 | 条件变化时触发响应，结合工具反馈决定继续、结束或调整动作 |
| Event Discovery | 固定问题 `Has a new event occurred?` | 筛选新活动与状态变化，形成后续写入的观察窗口 |

默认输入频率为 **1 Hz**，按时间顺序处理图像，从 `true / false` 的 logits 得到分数，不逐帧生成长文本。双阈值滞回减少状态抖动；公开事件筛选代码使用 **p > 0.5 开启、p < 0.3 关闭**，保留触发前 2 秒到关闭时刻的帧。

事件发现的训练标注关注新活动或状态变化：开头已经进行的活动不直接算新事件；单纯结束不一定构成新事件；中断后重新开始可计为新事件。正样本区间从事件开始延续到视觉证据充分的时刻。

**训练和使用要分开：**RoboBeats 基于 Qwen3.5 的 0.8B／2B／4B 模型，冻结视觉编码器，使用 LoRA 更新语言模型；监督来自连续视频的条件时间标签，损失包含逐步二分类与区间重叠监督。这是门控模型的专门训练；运行时积累记忆和 EDM 扩展工具，并不要求每个任务后再训练基础模型。

**实现边界：**论文§3.2描述增量缓存推理；本次核对的公开 `robobeats/gate.py` 复现路径按 100 帧分块、重叠 10 帧，块内因果前向，并显式设置 `use_cache=False`。该路径用于视频事件概率与筛选复现，不能据此声称已复现完整机器人持续在线系统。

来源：§3.1–3.4、附录B.1；官方 `robobeats/README.md` 与 `robobeats/gate.py`（核对于2026-11-05，未运行模型）。

## 记忆写入：保存什么，如何去重和维护

**Plastic Memory 使用图像文件与包含 JSON 字段的结构化记录。原始证据和当前语义解释分开管理，后续可以增加字段与索引。**

[对应论文原图](../reports/life.html)

关键帧统一记录以下字段；具体信息缺失时可以保持未设置。

| 字段 | 中文说明 |
|---|---|
| `ref`、`t` | 原始图像引用、采集时间 |
| `pose` | 可用的采集位置、机器人朝向、头部旋转和地图 |
| `source`、`trigger` | 来源与写入原因：巡检采样、用户确认、状态变化、事件或条件触发 |
| `event` | 关联活动的类型、标识及描述 |
| `segment`、`tracks` | 所属感知片段、出现的人物轨迹 |
| `fields` | 场景描述、物体、OCR、图文 embedding、人物与注册物体信息、View 归属及 builder 版本 |

写入与维护采用来源相关的规则，近似实现“增加新信息”的原则；论文没有把它定义为统一学习得到的记忆价值函数。

| 环节 | 规则 |
|---|---|
| 巡检采样 | 位移或转向足够、图像清晰、避开快速转向，排除视锥高度重叠的候选帧 |
| 主动感知 | 记录状态变化、事件、条件触发和人物到达；无状态变化时也可写入状态维持帧 |
| 用户确认 | 现场确认帧直接写入 |
| 空间关联 | 按同一地图中的位置、方向或估计注视区域，把重复观察归入同一个 View |
| 夜间代表帧选择 | 保留最早、最新和被事件／任务引用的证据，再按视觉覆盖与时间多样性选择代表帧 |
| 存储回收 | 无持有者引用的帧成为回收候选；先生成删除或降级计划，应用计划后才释放存储 |

代表帧预算只限制新增选择部分，不是整个 View 的总帧数上限。最新帧按时间排序确定；新观察到来后，之前的最新帧成为历史。

来源：§4.1、§4.3、附录C.1–C.4、表18。

## 记忆使用：检索、证据关联与历史补字段

**Agent 按问题组合过滤、关联、相似度检索、排序和图像核查，获得有时间与来源的证据，再回答或行动。**

例如“这个杯子是谁的”：先找杯子的历史记录，关联人物使用与交接事件，按时间排序，再回看原图。只看到某人拿过杯子不能直接认定所有权；未观察到的交接应保留为推断。

| 需求 | 记忆访问方法 |
|---|---|
| 某层有哪些杯子 | 先按楼层过滤，再按物体属性或相似度检索 |
| 某个人后来去了哪里 | 连接人物记录，按时间组织观察序列 |
| 物体过去在这里，现在还在吗 | 同一 View 返回问题最匹配的历史帧与最新观察；外观差异仍需图像核查 |
| 过去是否见过805门牌 | 对候选历史图像运行 OCR，回填门牌字段并建立文本检索索引 |
| 当前状态不确定 | 通过历史位姿导航到现场，重新观察确认 |

**历史重扫只处理需要的范围。**Builder 可以对某次巡检、某层楼或相关候选片段重新处理，输出保留来源引用；不要求每个新问题扫描全部历史。派生字段既可由人工编写的 builder 生成，也可由 EDM 构建的 builder 生成，不能把所有字段扩展都算成自主进化。

历史接口返回的是最近保留观察的实际时间，不一定正好等于请求时间。没有保留帧时，只有原始视频仍存在且可访问，才能尝试从视频缓冲中恢复；遮挡和漏检也不能直接认定物体消失。

来源：§4.2–4.4、附录C.3、C.5。

## 能力扩展：Explore–Distill–Mount 如何迭代

**Execution Agent 负责用现有能力完成日常任务；Coding Agent 负责围绕能力缺口进行程序探索与开发。EDM 复用 ReSight 的机制。**

[对应论文原图](../reports/life.html)

| 阶段 | 实际工作 | 保留下来的内容 |
|---|---|---|
| Explore | 看历史证据、写程序、调用模型，试出可运行解法 | 探索代码、中间结果、证据和解答记录 |
| Distill | 去掉写死的场景路径与答案，明确输入、输出和适用条件；回放 Execution Agent，依据答案与轨迹反馈修订 | 可重复调用的程序及使用说明 |
| Mount | 将验证后的能力注册到执行环境；必要时在相关历史记忆上运行 builder | `Tools`、`Skills`、`Builders` |

**具体例子：**文本检索无法可靠回答“见过几个这种展位”，Coding Agent 开发按照片检索。执行 Agent 回放后，把同一个展位的再次到访重复计数；再用位姿和时间合并 sightings。修订后的工具注册后，日常执行只需调用工具获得两个不同展位与支持帧。

能力更新包括代码、工具接口、技能说明和字段／索引生成器。记忆更新增加新证据或解释；两者相互配合，但不是同一种更新，也不是此处通过 PPO 更新 Manager 参数。

**验证边界：**LIFE 给出执行回放与反馈修订的流程，完整 EDM 算法和提示词指向 ReSight；本报告不补造固定测试集、通过阈值、最大修复次数或版本回滚规则。后面的留出实验验证了冻结能力复用，不能改写成测试时持续生成技能。

来源：§5.1–5.2、图12。构建成本包含探索、提炼、字段构建；后续执行 token 下降不等于全流程总成本同比下降。

## 实验结果：每组实验验证了什么

### 主动感知与经验筛选：LIFE 的新增评测

| 基准与指标 | 对照 | RoboBeats-2B |
|---|---:|---:|
| Charades-STA，因果在线 R@0.5 | Qwen3.5-2B：7.4% | **57.3%** |
| StreamingBench，首次触发±2秒准确率 | Qwen3.5-2B：22.8% | **56.0%** |
| SPOT-Bench，动作边界 T-F1@5 | Qwen3.5-2B：27.5 | **43.8** |
| 留出视频条件判断，AUROC | 同协议 Qwen3.5-2B：0.612 | **0.915** |
| ESTP-Bench，显式／隐式主动任务均分 | 均匀触发：19.5／34.4 | **33.6／40.2** |

Charades-STA 训练数据参与了 RoboBeats 训练。公开历史方法使用各自原协议，不能把不同协议的全部表格行都当成严格公平对照。来源：§3.6、表2–3、附录B.2–B.4、表11–14。

SSS-Bench 有 **171 个视频、618 个问题、14 个问题子类型**。筛选观察时不知道未来问题；对照采用匹配的写入帧预算、相同 Qwen3.8-27B reader。

| SSS-Bench 准确率 | 均匀采样 | RoboBeats-2B |
|---|---:|---:|
| 仅文本记忆 | 46.5% | **60.5%** |
| 文本记忆＋最多10张历史回看帧 | 54.7% | **63.1%** |

仅最近32秒图像、无记忆的对照为13.6%。门控筛选保留了更有利于后续问答的观察。来源：§3.4、§3.6、表15。

OVO-Bench 以下配置共用 Qwen3.8-27B reader，回答时使用文本记忆与最近16帧。准确率是 **EPM 与 ASI 两任务均值**，不是全部 Backward Tracing 三任务均值。

| 写入方案 | Writer输入，M tokens/小时 | EPM＋ASI平均准确率 |
|---|---:|---:|
| 全帧，27B writer | 0.338 | **70.0%** |
| OneStreamer PHCM，4B writer | 23.8 | 66.8% |
| RoboBeats筛选，27B writer | **0.186** | 66.6% |

相对全帧写入，writer 输入减少约45%，准确率下降3.4个百分点；这反映成本与保留证据的取舍。此项 token 是 writer 输入量，不含整个系统所有计算；OneStreamer 的 writer 模型也不同。来源：表5、附录B.6、表16。

### 记忆检索与技能复用：沿用 ReSight 的实验

| 实验 | 设置 | 结果与解释 |
|---|---|---|
| GOAT-core | 4场景、480查询；最多5候选，至少1个距目标≤1.5m算成功 | SR@5：MoM 80.6%，ReSight Agent 90.6%，Sol标注纯检索90.8%；各来源配置并非全部同协议重跑 |
| OC-NaVQA | 7序列、210查询；相同执行Agent，挂载EDM前后比较 | 位置误差33.10→24.72m，时间误差0.587→0.475min；二分类86.6%→82.1%，文本63.6%不变，不是各项均提升 |
| FindingDory | 91–100集596查询用于能力构建；81–90集597查询留出测试，能力冻结 | 留出总体成功率37.5%→65.8%，在线输入＋输出128.8K→39.4K/查询；去掉Explore仅46.4% |
| 真实巡检记忆查询 | 8F三个任务构建能力，冻结后测6任务×5次，含新问题与另一天1F记忆 | 全部12/30→30/30；仅后续新任务9/15→15/15；平均工具调用5.10→1.20，token 31.29K→12.31K/次 |

FindingDory 的未见集提升为28.3个百分点；空间／时间／多目标成功率分别为57.4%／83.3%／52.8%。复用阶段不再合成或修改能力；已有 builder 可以处理新记忆。在线 token 不包含前期探索、提炼及字段构建。巡检结果是**记忆查询成功率**，不能当作机械臂物理操作成功率。来源：§4.5、§5.3–5.4、表6–9。

### 24小时真机录像：集成记忆问答

Agibot A3 Ultra 录像覆盖 **2026-10-21 21:00至10-22 21:00**。先采集录像，再离线重建记忆：事件门控与背景差分筛选 → writer生成事件／状态描述 → 半小时整合与索引 → 回答问题。

构建后保留 **256个窗口、1,296张关键帧**。附录D报告记忆整合阶段363次writer调用，约8.04M输入、0.14M输出token；检测、跟踪与条件重扫成本未计入，不能将这些数当成端到端总成本。

6个问题涉及杯子归属、靠垫交接、外套位置、凌晨来访、首位到达者和午休结束。每配置每题重复3次，共18条问答记录，按人工rubric评分并允许部分分；各配置使用相同 **GPT-6.1-sol**。

| 指标 | Codex A：录像＋注册材料＋位姿 | Codex B：再提供已构建记忆 | LIFE：记忆及专用工具 |
|---|---:|---:|---:|
| 总分 | 24/30 | 28.5/30 | **29.5/30** |
| 得分率 | 80.0% | 95.0% | **98.3%** |
| 平均回答时间，秒/记录 | 961.5 | 554.7 | **80.6** |
| 平均输入token/记录，含缓存 | 4.39M | 3.06M | **172.8K** |

这些是**回答阶段**成本，不含前期记忆构建。LIFE 顺序接收两轮追问，coding-agent 对照把两轮一起作为一个提示输入；样本仅一天录像和6个问题，不能据此证明长期在线技能更新或物理操作能力持续提升。来源：§6、表10、附录D。
