## 问题与核心方法

仅凭执行反馈修改代码，可能一直优化错误的物理假设，例如抓取策略不合适、没有测量当前物体几何，或者没有确认前置步骤完成。

RoboAuto从示范提取物体知识，针对当前场景重新测量，再分阶段生成、验证和修改程序；原因不清楚时，另写实验检查物理假设。**开发阶段修改程序与知识，最终测试固定程序；论文未报告更新LLM／VLA参数。**

```text
LIBERO-90成功示范 → 初始物体知识
                         ↓
目标任务开发：测量 → 分阶段程序 → 执行／审核 → 修改或实验
                         ↓
验证有效的代码 → 技能库；执行证据 → 修正物体知识
                         ↓
固定最后一版程序 → 留出场景测试
                         ↓ 迁移知识与技能
真机重新测量与程序搜索 → 固定程序 → 独立位置测试
```

来源：§3、附录A.2–A.3、C、F；以下按本次讨论的问题整理，非原摘要译文。

## 经验初始化与组织

### 模型与接口

| 模块 | 来源与职责 |
|---|---|
| Coder | 仿真使用Claude Opus 4.6、1M上下文；查看初始画面，选择策略，编写测量、操作、验证及实验程序 |
| 感知与控制 | 扩展CaP-Bench评测接口；使用深度观测、Molmo2定位、SAM 3分割、Contact-GraspNet抓取候选及机器人控制原语 |
| Auditor | 独立语言模型会话，查看失败执行的视频、日志和阶段计划；具体型号未明确 |
| 知识构建VLM | 从示范视频提取证据并构建物体知识；具体型号未明确，不能认定为Astra或Opus |

CaP-X中，CaP-Gym提供代码运行环境与原语，CaP-Bench组织评测；RoboAuto将沿用、扩展的接口称为CaP-Bench evaluation interface。论文未完整列出各benchmark封装的全部函数签名。来源：§4.1、附录A.3、C.1、E.1。

### 90段示范如何成为经验

初始**物体知识**来自LIBERO-90：每个源任务1段成功示范，共90段；源任务与评测任务不同。

![原论文图12：从示范视频构建物体知识](../papers/assets/roboauto-knowledge.png)

VLM识别实体、划分交互事件，记录交互前状态、交互、交互后状态及视觉证据，最后评价episode结果；再跨记录归纳物体知识。

| 原始type取值 | 保存内容 |
|---|---|
| `affordance_constraints` | 物体适合怎样接触、抓取或操作，以及操作限制 |
| `spatial_relationships` | 空间关系、对齐与插入要求 |
| `effects_dependencies` | 动作效果、前置依赖及物体状态的视觉判断依据 |

### 原文字段：英文值保留，中文用 # 注释

附录C.1的删节示例实际展示五个键：`type`、`object_class`、`strategies`、`knowledge`、`open_quantities`。下面按Python字典展示字段摘录，策略和知识长文本只取片段，不是完整条目。

```python
{
    "type": "spatial_relationships",  # 知识类别
    "object_class": "Slab into a narrow open-topped compartment",
    # 适用的物体与交互情形
    "strategies": [
        "IN-PLANE VERTICAL SLOT INSERTION"  # 策略名称节选
    ],
    "knowledge": "Align yaw during the carry",  # 知识内容节选
    "open_quantities": [
        "slot width and long axis",  # 需要测量的槽宽与长轴
        "insertion depth"            # 需要确定的插入深度
    ]
}
```

正文还说明条目包含适用条件、支持事件和关联知识，并区分`[demonstrated]`、`[inferred]`、`[untested]`。上述删节示例未把这些全部列为独立键，因此不补造字段名。原文也说明`knowledge`已经删节。

物体知识层不保存特定场景数值、控制指令、任务专用计划或具体物体实例；知识给出策略和待测量，当前场景提供参数。书本案例中，条目由14次书本抓取示范支持，建议上边缘封面夹持，并要求测量书的厚度与朝向。来源：附录A.3、B.1、C.1、D.2。

### 技能与经验怎样更新

| 保存位置／层次 | 内容与更新方式 |
|---|---|
| `measurements.json` | 当前场景测量、观测依据与未解决条件；新观测矛盾时修正 |
| `diagnosis.md` | 每轮追加失败、原因假设、实验预测、支持或否定假设的证据，不覆盖早期记录 |
| 物体知识层 | 用程序执行与主动实验的物理证据，支持、质疑或修正已有知识及条件 |
| 可执行技能层 | 保存通过当前搜索池验证的程序组件；任务解决后归入技能库，供检索与组合 |

**明确从90段示范初始化的是物体知识层。**论文未完整说明初始技能库的规模、构建任务及次数；不能说90段视频直接生成完整技能库。技能抽取、去重、冲突合并和库维护提示词也未完整披露。来源：附录A.3、C.1、C.3。

## 开发迭代与留出测试

### 先测量，再生成分阶段程序

Coder先读任务、初始画面和相关条目的`open_quantities`，编写`experiments/00_measure/`。程序调用感知API分割物体，将深度反投影为点云，计算当前任务需要的位置、尺寸、方向和间隙，写入`measurements.json`，再建立`diagnosis.md`、`plan.md`和阶段文件。

书本案例测得厚度2.8 cm，检查两个相机观测的一致性，并确认5.2 cm宽的槽位能容纳薄板；具体点云过滤、拟合与测量算法没有完整公开。来源：附录C.2、D.2、E.1。

```text
plan.md                 阶段顺序、目标物体状态、验证方法
stages/01_*.py          第一阶段操作与验证
stages/02_*.py          第二阶段操作与验证
experiments/NN_*/       假设、预测及独立诊断实验
diagnosis.md            持续追加的诊断记录
```

阶段文件在一次rollout内按顺序执行，共享Python命名空间和连续的物理场景。每阶段以`stage_done(ok, evidence)`结束，依据新观测判断物体是否达到预期状态；夹爪闭合或机械臂到位本身不是成功证据。

阶段验证失败后停止后续阶段。Auditor检查失败执行的视频与日志，返回最早未完成的阶段；Coder修改阶段代码、验证器或整体计划，再重置场景、从头运行候选程序。原因不清楚时，另外设计实验检验假设。成功场景以环境任务判定为准，不经过失败视频审核。来源：附录C.3、E。

### 每个benchmark如何开发，预算是多少

单位是**每个目标任务—扰动设置**，并非整个benchmark共用一份程序。每次新版本先在2个场景运行，优先选当前阶段之前失败的场景；通过后检查当前搜索池，搜索池从5扩展到10、15个场景。全部解决或预算耗尽后停止搜索。

**1次rollout＝1份程序在1个开发场景执行一次。**主动换视角和诊断实验的程序执行同样占用预算；预算不等于代码修改次数或模型调用次数。

| Benchmark／类别 | 评测设置数 | 每设置开发预算 | 每设置留出测试 | RoboAuto成功率 |
|---|---:|---:|---:|---:|
| LIBERO-PRO Object：指定物体抓放 | 20 | 45次 | 50次 | 98.7% |
| LIBERO-PRO Spatial：相对位置识别与放置 | 20 | 45次 | 50次 | 94.8% |
| LIBERO-PRO Goal：抽屉、炉灶、推物体 | 20 | 45次 | 50次 | 73.7% |
| LIBERO-PRO Long：多阶段依赖 | 10 | 55次 | 50次 | 73.4% |
| LIBERO-Plus：相机与布局变化 | 6 | 短任务45次；长任务55次 | 50次 | 90.3% |
| Robosuite：接触、对齐与双臂协作 | 7 | 45次 | 100次 | 90.6% |
| RoboTwin 2.0：跨仿真器与本体迁移 | 4 | 11次 | 50次 | 91.5% |

设置数按任务×扰动计算。LIBERO-PRO每类10个任务，各测位置扰动与任务扰动，共20个设置；三个短程类别平均89.1%。LIBERO-Plus是3个基础任务×2种扰动：Spatial、Goal各2个设置，预算45次；Long-derived 2个设置，预算55次。来源：§4.2、附录A.1–A.2、B.2、B.4。

### 测试时运行固定程序

开发场景seed为110000–110014；留出测试seed通常1–50，Robosuite为1–100。**搜索结束后固定最后一版程序**，逐个测试场景独立执行，由环境成功判定统计任务成功率。程序可调用感知、重新计算参数、执行已有分支和重试；不会根据测试失败让Coder重写程序。

测试结果不进入Agent的开发反馈，不更新任一知识层。每个独立评测任务恢复对应的初始知识条件，并非让所有测试任务依次累积经验。该协议主要测试目标任务开发后的新场景泛化。另有3个任务各做3次独立搜索，最终程序仍在相同50个测试场景上评估，用于考察搜索随机性。来源：附录A.2–A.3、B.7。

### 与PyRUA-Lean的区别

| 方面 | RoboAuto | PyRUA-Lean |
|---|---|---|
| 代码与交互 | 分阶段程序，在开发场景重置、运行、修改 | Python cell内组合原语，当前episode读取反馈后继续 |
| 经验 | 保存物体知识及验证过的代码技能 | 主比较关闭跨episode记忆和技能积累；episode内保留变量和函数 |
| 参数更新 | 搜索修改程序和知识，不训练Coder | Astra主比较不训练；另有Coder实验用GRPO更新Qwen3.5-4B |

两者都支持程序分支、计算和局部重试，区别不在代码长短。来源：RoboAuto附录C、E；[PyRUA-Lean v2 §3、§5](https://arxiv.org/html/2610.01939v2)。

## Sim2Real怎样进行

```text
LIBERO物体知识＋搜索中验证的技能
                ↓ 迁移分层知识库
真机当前画面／深度 → 检索与重新测量
                ↓
Opus 5在真机接口上生成、执行和修改程序
                ↓ 每任务最多10次搜索rollout
固定程序 → 每任务20次独立位置评测
```

**硬件：**WidowX AI机械臂、Intel RealSense D405 RGB-D相机、Logitech C920 RGB相机。对比方法使用相同硬件、传感器与控制接口。

**迁移内容：**LIBERO获得的分层知识库，包含物体知识与可执行技能；3个真机任务均不同于知识库构建任务。当前几何重新测量，动作通过目标机器人接口实现，不是回放仿真关节轨迹。

**真机开发：**RoboAuto与ASPIRE均用Opus 5、1M上下文，每任务10次搜索rollout预算；人判断执行是否成功，替代仿真环境判定，并在每次rollout后重置场景。开发期间可以根据反馈修改程序。

**正式评测：**每方法每任务20次，初始位置从相同区域独立采样，与开发位置不同；固定程序执行，由人评价阶段完成比例。真机实验含目标任务上的程序搜索，不属于未经目标任务开发的直接部署。物理实验仍需人工维护和安全监护。

**实现边界：**论文未完整给出相机外参标定、控制封装和技能逐项适配细节，不能补写成全部自动完成。来源：§4.4、Limitations、附录F。
