# Embodied Turing Machines / COAP 阅读笔记

论文：[Embodied Turing Machines](https://arxiv.org/html/2610.12369v1)

## 1. 对我们做 CAP 的意义

这项工作为**通过代码迭代完成机器人任务**提供了仿真实验支持：让编码 Agent 根据失败反馈修改程序，将能力积累在共享代码库中，最终冻结程序进行评测。

- **开发阶段**：运行任务 → 分析失败 → 修改代码 → 验证 → 合并。
- **执行阶段**：观测 → 更新显式状态 → 程序决策 → 执行动作 → 检查和重试，不调用 VLM/VLA。

论文在 RoboDojo 的42项任务上取得 **70.24%** 的整体成功率，其中40项有程序，2项没有程序。全部结果来自仿真，尚未进行真机验证。

## 2. 迭代时间与探索预算

附录表6记录了以下新任务的开发时间，均从开始开发起累计：

| 任务 | 首次评估 | 首次成功 |
|---|---:|---:|
| 做吐司 | 3.2小时 | 4.7小时 |
| 挂杯子 | 3.2小时 | 5.2小时 |
| 扫方块 | 3.9小时 | 6.4小时 |

论文没有完整披露每个任务的代码修改轮数、候选程序数量、累计开发与验证轨迹量，以及总开发时间、token和费用。

每任务 **3个种子 × 50个布局＝150条 episode** 是最终评测规模，不是开发探索量。

验证集用于筛选代码改动；第3节的任务成功率来自论文报告的最终测试结果。

我们需要建立的度量是：

> **累计代码迭代次数、累计环境交互次数 → 固定测试集成功率。**

同时记录旧任务是否退步，以及共享模块是否降低了新任务的开发成本。

## 4. 代码规模与技术分层

| 层级 | 职责 | 主要技术与例子 | 代码量 |
|---|---|---|---:|
| **任务程序** | 定义步骤、目标与完成条件 | 任务阶段管理、子目标排序、机械臂分配、显式记忆、重试；例如挂杯子的完整流程 | 23,500行 |
| **物体类型模块** | 封装物体特性和处理方法 | 杯口测量、物体朝向判断、抓取位置选择等 | 28,500行 |
| **通用操作模块** | 提供跨物体动作 | Grasp、Pick、Place、Push、Pour；抓取候选生成、抓持检查、搬运和结果验证 | 5,400行 |
| **感知模块** | 从图像测量环境状态 | NumPy、OpenCV、网格投影遮罩、连通区域、射线—平面求交、三维形状拟合、腕部相机复测 | 5,300行 |
| **运动模块** | 计算并执行机器人运动 | IK（逆运动学）、可达性判断、Collision Checking（碰撞检测）、运动规划 | 3,300行 |
| **合计** | | | **约66,000行** |

其中，通用操作、感知和运动基础库合计约 **14,000行**。代码量采用论文统计，职责和例子用于解释架构。

环境与任务状态通过 `WorldState` 等显式结构保存。**COAP测试时不使用SAM**；论文将SAM列为其他代码策略采用的学习式感知组件。

## 5. 程序复用

**新任务运行涉及的代码中，约83%来自共享库。**

| 方式 | 复用内容 | 例子 |
|---|---|---|
| **组合已有模块** | 感知、抓取、搬运、放置与验证 | 调用 `transfer`，复用抓取候选、IK、碰撞过滤、复测和放置检查 |
| **继承任务流程** | 保留已有流程，只修改局部规则 | 按语言分类继承已有分类任务，替换物体到篮子的分配规则 |
| **扩展共享函数** | 为已有操作增加可选行为 | 增加 `lift_dir` 参数，支持斜向提起物体 |

各层最常用模块在40个有程序任务中的覆盖率：

| 层级 | 任务覆盖率 |
|---|---:|
| 感知 | 100% |
| 运动 | 100% |
| 通用操作 | 78% |
| 物体类型模块 | 18% |
| 任务程序 | 2.5% |

83%描述新任务的代码复用程度；上表描述每层最常用模块被多少任务使用，两者口径不同。

## 6. 对我们后续工作的启发

- 持续迭代CAP，同时保留固定测试集，记录成功率随迭代和交互预算的变化。
- 将任务程序、物体处理、通用动作、感知和运动分层，避免每个任务重复实现完整流程。
- 衡量复用的实际收益：新增代码量、首次成功时间、达到目标成功率的交互量。
- 关注装箱、挂杯子、扫方块、插入和长程整理等尚未解决好的任务。
- 将仿真成功率与真机可用性分开验证。
